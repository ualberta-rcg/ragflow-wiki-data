Béluga is a heterogeneous and versatile cluster designed for general-purpose computing; it is located at [École de technologie supérieure](http://www.etsmtl.ca/). Its name recalls the [beluga whale](https://fr.wikipedia.org/wiki/B%C3%A9luga_(c%C3%A9tac%C3%A9)), a marine mammal living in the waters of the St. Lawrence River.

## Characteristics
Our policy dictates that Beluga compute nodes do not have internet access. To request an exception, please contact [technical support](../support/technical_support.md) explaining your needs and reasons. Note that the `crontab` tool is not available.

Each job should run for at least one hour (or at least five minutes for test jobs), and a user cannot have more than 1000 jobs (running and pending) at a time. The maximum job duration is 7 days (168 hours).

## High-Performance Networking

The Mellanox Infiniband EDR (100 Gb/s) network connects all cluster nodes. A central 324-port switch aggregates island connections with a maximum blocking factor of 5:1. Storage servers are connected with a non-blocking interconnect. The architecture supports multiple parallel jobs with up to 640 cores (or more) thanks to non-blocking networking. For larger jobs, the blocking factor is 5:1; even for jobs spanning multiple islands, the interconnect provides high performance.

## Job Monitoring
From the former Beluga [Metrix](../software/metrix.md) portal, it was possible to monitor CPU and GPU compute jobs in "real-time" or past jobs to maximize resource utilization and reduce queue waiting times.

For each job, you could visualize:
* CPU core utilization;
* Memory usage;
* GPU utilization;

It is important to utilize allocated resources and adjust your requests when compute resources are underused or not used at all. For example, if you request four CPU cores but only use one, you should adjust your submission file accordingly.
